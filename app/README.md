# ICU QuickRef (v2)

Offline-first ICU nursing quick-reference PWA. **Reference aid only. DRAFT: not clinically reviewed.**
Plain HTML/CSS/JS, no framework. Deploy the folder as static files (no build step required to deploy).

## Files
| File | Purpose |
|---|---|
| `index.html` | Shell. No inline scripts/styles (strict CSP; a meta CSP copy is included). `noindex`. |
| `theme-init.js` | Applies the saved theme before first paint (theme is stored as JSON `"light"`/`"dark"`). |
| `data.js` | **All clinical content** (owned by the content editors). |
| `app.js` | App logic. Generated by concatenating `/workspace/v2-build/parts/*.js` with `build.sh`; editing `app.js` directly is fine too (run `node --check app.js`). |
| `styles.css` | Styles. Dark theme reds: `--red` for text, `--red-fill` (>= 4.5:1 with white) for filled badges. |
| `sw.js` | Service worker (see "Updates"). |
| `version.json` | `{version, date, withdrawn, message, minSafe?, withdrawnVersion?}`. Recall / freshness signal. |
| `manifest.json` | PWA manifest (`orientation: any`). |
| `_headers` | Cloudflare Pages / Netlify headers: CSP, nosniff, `Referrer-Policy: no-referrer`, Permissions-Policy, `X-Robots-Tag: noindex`, no-cache for sw.js / version.json / data.js / index.html. |
| `robots.txt`, `404.html` | Disallow all crawling; real 404 (stops SPA fallback caching junk). |
| `scripts/check-release.js` | Pre-deploy gate: syntax, version sync, precache list, no inline script/style. |

## Data schema supported by app.js
- List items (`glance`, `warnings`, `recognize`, `actions`, `monitor`, `meds`, `escalate`) may be plain strings or `{id, t, s}`; `s` = `RN` | `ORDER` | `PROV` (badges "RN" / "Per order" / "Provider"). A leading `!` in the text marks a CALL step.
- Checklist ticks are keyed by item `id` (fallback: hash of the text). **Keep ids stable** when editing text; a new id = a new step.
- Condition flags: `emergency: true` (Home emergency grid; falls back to the 4 legacy ids if none), `timer: true` (or id containing `arrest`) shows the code-timer dock, `keywords: [...]` (or a string), `warnings: [...]` (red box near the top).
- `meta: {version, date, status, expires, scopeTags, medNotice, disclaimer, scope}`; legacy top-level `version/date/reviewStatus/reviewedBy/facilityNote` still work. `status` not starting with "approved/reviewed" shows a DRAFT strip on every condition page. After `expires` (end of that day) a blocking red screen appears.
- Search synonyms/abbreviations live in `app.js` (`ALIAS_SRC`); targets are condition ids (`x`, `x-*`, or `prefix*`). Unknown ids are ignored.

## Releasing (every content or code change)
1. Bump `meta.version` in data.js, `version` in `version.json`, and `CACHE_VERSION` in `sw.js` (must contain the version).
2. `node scripts/check-release.js` must pass. Optionally `node /workspace/reviews/validate-data-v2.js .`
3. Deploy. Devices see a persistent "Updated content is available - Reload to update" banner; the reload waits for the new service worker.

**Recall:** set `"withdrawn": true` and a `message` in `version.json` and deploy: online devices show a blocking red screen at next launch/foreground.

## Updates / offline (sw.js)
- Network-first (4 s timeout, cache fallback) for navigations/index.html, `data.js`, `version.json`; cache-first for other static assets from the versioned cache only.
- Atomic precache with `cache.addAll` (bypassing the HTTP cache); `clients.claim()` on activate; `skipWaiting` only when the page asks (update banner).
- The page fetches `version.json` on launch, on foreground and every 30 min, and records "last verified online". If not verified for > 14 days an amber banner appears.

## Patient-session state (device only)
- Ticks expire 12 h after ticking and on any content-version change; "New patient: clear all ticks" (Home, condition page, About) asks for confirmation.
- Code timer: separate Start / End controls, confirmations for End / New code / Clear log, 600 ms double-tap guard, duplicate epi/shock taps within 2 s ignored, Undo last. Warning after 60 min; on launch with a timer > 2 h old you are asked to end it. A stopped log is discarded after 12 h.
- Rhythm check every 2 min: 3-tone beep (repeats every 10 s until acknowledged, max 6), vibration (Android), flashing full-width banner on every screen. Audio unlocks on any tap and resumes when the page becomes visible; wake lock is re-acquired on visibility. iOS: ring switch must be ON and the app must stay in the foreground.
- Every localStorage read is shape-validated; a failed render shows a recovery screen with "Reset app data" (also in About).

## Testing
Test scripts (puppeteer-core + system Chrome) are in `/workspace/v2-build/test/` (`t-smoke.js`, `t-func.js`, `t-sw.js`, `t-fatal.js`, `search-node.js`); run `./mksite.sh` first (tests use a copy of this folder).
